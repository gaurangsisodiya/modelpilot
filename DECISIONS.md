# - WSL and Docker data on E:, since C: had 35 GB free.
- Code lives in ~/code inside WSL, not /mnt/c or /mnt/e: cross-system file access is slow.
- Python 3.12 via uv, one environment per repo.
- VS Code for these repos: its WSL support is the most reliable.
- NVIDIA free API first; Together ($15) only if NVIDIA can't cover tool calling or Week 3 load tests.
- RAM upgraded to 16 GB (2 × 8 GB); WSL memory raised to 8 GB, so Weeks 4–5 run locally without a cloud VM.
- Cost per query = input_tokens × input_price/1M + output_tokens × output_price/1M, using each model's real token counts (dataset has no cost column to check against).
- Score metric = mean of `performance` (squad keeps partial F1 credit); always labelled "avg score", never "accuracy".
- Oracle = per query, the model with the highest performance; ties broken by lowest cost. No correctness threshold.
- Queries no model answers: all tie at 0, so the oracle picks the cheapest model (follows from the rule above).
- Baselines "cheapest" and "best" fixed models are picked from train-split stats, then evaluated on test (no test leakage).
- Router cost term = kNN-predicted cost (mean cost of that model on the k nearest train queries), since real output tokens are unknown before calling.
- kNN uses k = 10 (fixed, no tuning), cosine similarity on normalised MiniLM embeddings.
- Router compares cost in $ per 1,000 queries so lambda values stay readable (0.1–10).
- Query embeddings cached in cache/ (gitignored); embedding all 8,218 queries takes ~7 min on CPU.
- PyTorch installed from the CPU-only wheel index (pyproject [tool.uv.sources]) — no GPU.
- v2 router change 1: neighbours weighted by cosine similarity (weighted mean of score and cost); remaining utility ties (to 9 dp) go to lower predicted cost instead of alphabetical order.
- v2 router change 2: embed only the question text (text after "[User Query]\n", minus leading "Question:"/"## Question:"/"Task:"/"Complete the following function:" labels); options, passages and code kept. Cache cleared and rebuilt.

The tie goes to qwen2.5-7b on 2,628 of the 4,199 (62.6%); overall 2,630 labels (58.6%) are qwen2.5-7b, only 2 of them from queries where it is the single best.

- Phase 8 validation: 20% of train queries held out per task (seed 0, 897 queries); all tuning uses only fit/validation, and test is run once at the end by compare_learned.py, which reads settings from validation_decision.json. The decision file was committed before the test run.
- Phase 8 learned router: one MLPRegressor (all 18 model scores at once, so squad's F1 needs no thresholding) plus a Ridge regression for per-model cost, same utility rule as kNN. Settings picked by validation MSE: hidden=256, alpha=1, Ridge alpha=0.1 (grids extended once when the first pick sat on the edge).
- Phase 8 kNN k=20 (was 10) and API default λ=1 (was 3), both from validation. λ rule: largest λ whose validation avg score is within 0.01 of the best λ. v1–v3 results keep k=10.
- Phase 8 replacement rule: the MLP replaces kNN only if, at the default λ on validation, its paired-bootstrap 95% CI is above 0 and its cost is ≤ 1.1× kNN's. Validation: −0.012 [−0.032, +0.005] → kNN stays default.
- Phase 8 test (run once): MLP scores higher than kNN at every λ; at λ=1 +0.014 [+0.003, +0.024] but 1.20× the cost. Not used to change the default (that would be tuning on test). Validation and test disagree, so the 897-query validation slice is too small to separate them.

- Phase 9 gateway: model "auto" routes (kNN k=20 restricted to the two models, default λ from ROUTER_LAMBDA=1), "small"/"large" force a backend (needed for the all-small/all-large GuideLLM runs); optional body field "lambda".
