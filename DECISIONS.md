# - WSL and Docker data on E:, since C: had 35 GB free.
- Code lives in ~/code inside WSL, not /mnt/c or /mnt/e: cross-system file access is slow.
- Python 3.12 via uv, one environment per repo.
- VS Code for these repos: its WSL support is the most reliable.
- NVIDIA free API first; Together ($15) only if NVIDIA can't cover tool calling or Week 3 load tests.
- RAM upgraded to 16 GB (2 × 8 GB); WSL memory raised to 8 GB, so Weeks 4–5 run locally without a cloud VM.
- Cost per query = input_tokens × input_price/1M + output_tokens × output_price/1M, using each model's real token counts (dataset has no cost column to check against).
- Score metric = mean of `performance` (squad keeps partial F1 credit); always labelled "avg score", never "accuracy".
- Oracle = per query, the model with the highest performance; ties broken by lowest cost. No correctness threshold.
- Queries no model answers: all tie at 0, so the oracle picks the cheapest model (follows from the rule above).
- Baselines "cheapest" and "best" fixed models are picked from train-split stats, then evaluated on test (no test leakage).
- Router cost term = kNN-predicted cost (mean cost of that model on the k nearest train queries), since real output tokens are unknown before calling.
- kNN uses k = 10 (fixed, no tuning), cosine similarity on normalised MiniLM embeddings.
- Router compares cost in $ per 1,000 queries so lambda values stay readable (0.1–10).
- Query embeddings cached in cache/ (gitignored); embedding all 8,218 queries takes ~7 min on CPU.
- PyTorch installed from the CPU-only wheel index (pyproject [tool.uv.sources]) — no GPU.
- v2 router change 1: neighbours weighted by cosine similarity (weighted mean of score and cost); remaining utility ties (to 9 dp) go to lower predicted cost instead of alphabetical order.
- v2 router change 2: embed only the question text (text after "[User Query]\n", minus leading "Question:"/"## Question:"/"Task:"/"Complete the following function:" labels); options, passages and code kept. Cache cleared and rebuilt.
- v1 → v2 test results (avg score / total cost): λ=0 0.776/$1.123 → 0.736/$0.576; λ=0.1 0.735/$0.450 → 0.732/$0.490; λ=0.3 0.729/$0.337 → 0.727/$0.354; λ=1 0.722/$0.129 → 0.715/$0.137; λ=3 0.720/$0.085 → 0.711/$0.089; λ=10 0.709/$0.059 → 0.701/$0.059. Raw CSVs in results/v1 and results/v2.

- Template stripping tested in v2 and reverted: the instruction text carries task-type signal; same-task neighbour share fell 0.58 → 0.56 without it.
- v1's λ=0 score (0.776) was inflated by alphabetical tie-breaking: ties went to cogito-v2-1-671b, which happens to be the strongest model. With cost tie-breaks (v3) λ=0 gives 0.736 at $0.518.

- Phase 5 /chat model choice = live availability: at startup fetch NVIDIA /v1/models; call the routed model on NVIDIA if its api_model_id is listed, else fall back to the listed candidate with the highest train avg score. Only 2 of 18 candidates are listed (2026-10-31): mistral-7b-instruct-v0.3 and openai/gpt-oss-20b (dataset says Together, but NVIDIA serves it); the other 5 "NVIDIA" models are retired. So today's fallback is gpt-oss-20b.
- /route and /chat default λ = 3 (Phase 4 sweet spot), overridable with "lambda" in the request body.
- NVIDIA client: 60 s timeout, 1 retry; API errors return HTTP 502 without echoing details.
- kNN weights computed in float64 (float32 embeddings gave predicted scores like 1.0000000427); v3 sweep re-run and identical.
- Known limitation: live queries lack the dataset's "[System Instruction]" template, so their neighbours are less task-aware than in the offline evaluation.
- Tests use tiny hand-made DataFrames/vectors (tests/conftest.py), so they need no dataset, encoder or network. The FastAPI endpoints are not unit-tested; they were checked manually against the live API in Phase 5.

Its benchmark_pipeline trains + evaluates routers in one call per (router, alpha); we drive its run_job() via scripts/llmrouter/run_llmrouter_pipeline.py, only redirecting data/results dirs and mfrouter text_dim. - LLMRouter cost sweep: alpha = 1.0, 0.8, 0.6, 0.4, 0.2 (beta = 1 - alpha) on its min-max normalised reward alpha*perf - beta*cost, as its README suggests; this is its counterpart to our λ.
